Model & evidence

How the model works, how it performed, and where it falls short. A student research prototype.

Important: Performance on a dataset does not establish clinical validity. This model is for a course project and must not be used for patient-care decisions.

How it works

01 · Input

Routine blood count values (WBC, differential, hemoglobin, platelets and more). Ratios such as NLR, PLR and MLR are calculated automatically.

02 · Model

A regularised logistic regression gives a screening score from 0 to 1. Fields left blank are treated as typical values.

03 · Flag

A flag is raised when the score reaches the threshold. The threshold was set on development data to catch about 90% of leukemia cases.

04 · Explanation

Each value's push up or down on the score is shown, so a flag is never a black box.

Data: LeukoAlert routine CBC dataset

11 files from 7 hospitals. Models are trained only on the development files; every other file is used only for testing. Counts are raw records before cleaning.

Limitations

Key limitation: some cases are missed at unseen hospitals

On hospitals the model never saw in training, recall was about 87%, below the 90% target. That means roughly 1 in 8 leukemia cases there was missed. Cases with near-normal counts are the hardest to catch.

  • This is a student research prototype, not a diagnostic tool.
  • The score is not a probability. Training data is 33% leukemia, while the real-world test set has about 4% leukemia. At that rate, about 1 in 4 flagged people had leukemia (precision 24%).
  • The dataset has no patient identifiers, so repeat blood tests from one person may appear in both training and test data.
  • The training data may not represent Pakistani patients. Local validation would be needed before any real use.
  • Missing values, laboratory units and data quality affect results. Feature contributions explain the model, not medical causation.
